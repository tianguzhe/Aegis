# 修改主密码与密钥轮换设计

状态：已实现（方案 A）。代码见 `AegisCore/VaultRotation.swift`、`VaultStore.replaceVault`、`VaultSession.changeMasterPassword`，测试见 `KeyRotationTests`。对应 [深度审查](REVIEW_2026-11-19.md) P0"修改主密码 / 密钥轮换"。

## 1. 目标

用户在已解锁的设备上设置新主密码，同时：

- 生成新的保险库密钥 K2 和新的恢复密钥；
- 用 K2 重新加密本机保留的版本；完整保留历史是默认选项；
- 旧主密码、旧恢复密钥、旧生物识别密钥都打不开新保险库。

不在范围内：撤销已导出的备份或其他设备上的旧副本（它们由 K1 保护，无法远程作废）；物理擦除 SQLite 空闲页中的旧密文（与现有"不物理擦除历史密文"的约定一致）。

## 2. 方案选择

| 方案 | 做法 | 影响 |
|---|---|---|
| **A. 新保险库身份 + 复用 `BackupMigration`（推荐）** | 新建 header（新 vaultID、新盐、K2、新恢复密钥），把当前库完整迁移进去，事务内替换本机数据库 | `VaultHeader`、ABB v1 备份格式、局域网协议、自动填充快照格式**都不变**；迁移逻辑已有测试 |
| B. header 引入 epoch | 同一 vaultID 下 epoch 递增，header 可被更高 epoch 替换 | 要改 `VaultHeader` 格式版本、ABB v1 的定长头部、校验逻辑、局域网协议，改动面大 |

`BackupMigration` 按 `(旧 vaultID, 新 vaultID, 原 ID)` 确定性地生成新 ID。导入前驱保险库的备份时，按加密谱系中的顺序逐跳映射条目、版本和父版本 ID。这样能在多次轮换后识别同一版本，并继续应用永久删除标记。

## 3. 流程（`VaultSession.changeMasterPassword`）

前置条件：已解锁；没有未保存的草稿（草稿用 K1 加密并引用旧 ID，先保存或放弃）；没有其他进行中的操作。

1. **验证当前主密码**：用独立的 `VaultCrypto` 实例解包当前 header，不影响会话。
2. **取快照**：`store.snapshot()` 读出 header 和全部版本，并取当前 K1。
3. **创建新保险库**：在另一个独立的 `VaultCrypto` 实例里执行 `create(password: 新主密码)`，得到新 header、K2 和新恢复密钥。
4. **迁移**：使用 `BackupMigration` 重加密历史、冲突分支和删除标记。用户选择压缩时按第 9 节裁剪。
5. **自检**：用 K2 解出的条目与用 K1 解出的条目逐一比对（ID 按映射对应，内容一致），不一致则中止。
6. **先持久化新恢复密钥**：把 `pendingRecoveryKey` 写入新 vaultID 的本机状态文件。与 `create()` 相同，保证中断后仍能完成恢复密钥确认。
7. **事务替换**：新增 `VaultStore.replaceVault(expected:snapshotIDs:header:revisions:)`。在一次 actor 调用内校验当前 header 与版本 ID 集合仍与快照一致（防止期间有保存），然后删除旧 header 和全部旧版本、写入新数据，一次 `save()` 提交；失败则 `rollback()`，什么都不变。
8. **切换会话**：会话密钥换成 K2，更新 `header`。
9. **生物识别**。删除旧钥匙串条目。若会话仍然解锁且之前已开启生物识别，则用 K2 登记新凭据，登记成功后再开启新库的 `biometry.<vaultID>` 设置。旧凭据删除失败或新凭据登记失败时显示对应警告，已完成的轮换继续有效。平时关闭生物识别时，只有成功删除凭据或确认凭据已不存在，才会关闭开关。
10. **清理**：删除旧 vaultID 的本机状态文件。替换数据库前已撤下旧自动填充快照，解锁状态下的 `refresh()` 发布新快照。
11. **展示新恢复密钥**：复用现有的恢复密钥确认页。

中断语义：第 7 步提交前中断，旧库原样保留，新状态文件成为无主文件，无害；提交后中断，用新主密码解锁，并继续完成恢复密钥确认。

## 4. 界面

设置 → 安全 → "修改主密码"：

- 输入当前主密码、新主密码、确认新主密码（新主密码至少 12 位，与创建时规则相同）；
- 可勾选「同时压缩历史版本」；
- 说明文字：
  - 旧的导出备份仍可用旧主密码打开，建议删除；
  - 其他设备上的保险库不会自动更新，需要重新加入；
  - 恢复密钥会更换。
- 执行中显示进度，禁止关闭；完成后弹出新恢复密钥确认。

## 5. 安全边界

| 场景 | 结果 |
|---|---|
| 旧主密码 / 旧恢复密钥 | 打不开新 header |
| 持有 K1 的丢失设备 | 只能看到轮换前的数据；无法解密轮换后的任何新版本 |
| 轮换前导出的备份 | 仍可用旧凭据打开（无法作废）；导入当前库时去重 |
| 其他已加入的设备 | 仍是旧库，需要重新加入。目前没有"移除本机保险库"功能，需要另做 |

## 6. 测试

AegisCore / AegisStorage 单元测试：

- 新主密码、新恢复密钥能打开；旧主密码、旧恢复密钥、K1 都不能；
- 轮换前后条目一致，包括回收站、冲突分支和删除标记的压制效果；
- `replaceVault` 在快照之后有新版本写入时拒绝，失败时什么都不写；
- 轮换后导入轮换前的旧备份，新增版本数为 0；
- 迁移结果中没有残留旧 vaultID 的版本。

## 7. 决定（2026-11-19）

- [x] 采用方案 A。
- [x] 允许新主密码与旧主密码相同，界面提示建议更换；密钥、盐和恢复密钥仍全部更换。
- [x] 有打开的编辑器或保留的草稿时拦截，提示先保存或放弃。

## 8. 实现备注

- 迁移后会把新旧两份数据各自解密出的条目逐一比对（去掉 ID 后），不一致就中止，不写入任何东西。
- `replaceVault` 原地更新 header 行，删除其余全部行，再插入新版本，在同一个事务中提交。
- 新恢复密钥直接显示在"修改主密码"页面里（`recoveryPresentedInline`），避免在 Mac 设置 sheet 之上再从根视图弹出第二个 sheet。
- 提交之后如果会话已被锁定，保持锁定状态；下次用新主密码解锁时显示恢复密钥。

## 9. 可选历史压缩

验证并解密旧版本图后，每个可见条目保留全部当前分支，包含回收站中的分支。每个永久删除条目保留一个删除标记。保留的版本以空父列表重新加密，因此压缩后的备份携带完整的新版本图。事务成功后，旧版本行占用的 SQLite 页可供后续写入重用。

轮换将前驱保险库 ID 依次追加到加密内部记录的 `predecessorChain`。压缩时，把链上的所有前驱及刚被替换的库 ID 标记为已退役，再清空链。备份和局域网首次加入均携带该记录，按条目恢复时也会保留它。已退役的祖先备份只能恢复到独立保险库。旧开发版使用无序前驱集合，读取该谱系时会报错，因为无法可靠还原映射顺序。
