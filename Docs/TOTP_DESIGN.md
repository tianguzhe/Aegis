# TOTP 两步验证码设计

目标：登录条目可保存两步验证密钥，显示并复制当前动态码。从 1Password 迁移时验证码不再需要手动重设。

## 范围

首版包含：

- 仅 TOTP（RFC 6238）。支持 SHA1 / SHA256 / SHA512、6 至 8 位、自定义周期（默认 30 秒）。
- 仅登录条目，每条最多一个密钥。
- 录入方式：粘贴 `otpauth://totp/...` 链接、粘贴 Base32 密钥、选择二维码图片（Vision 识别，不需要相机权限）。
- 1Password CSV 的 `OTPAuth` 列直接导入。

首版不包含：

- **HOTP**：计数器每用一次就要写一个新版本，多台设备各自使用时必然产生冲突，不适合不可变版本图。遇到 `otpauth://hotp` 时明确拒绝，不静默丢弃。
- Steam Guard 等非标准变体。
- 相机实时扫码：需要新增 `NSCameraUsageDescription` 和相机流程，放到二期。
- 系统自动填充验证码：依赖自动填充权限，免费签名下不可用。

## 数据模型

`VaultItem` 新增可选字段：

```swift
public var oneTimePassword: String?   // canonical otpauth://totp URI
```

- 保存规范化后的 `otpauth://` URI，而不是拆开的字段。URI 本身包含算法、位数和周期，以后支持新参数时不用改模型。
- 字段在条目 JSON 内，与密码一起被 AES-GCM 加密，AAD 规则不变。**不改加密、header、ABB 备份格式和局域网协议。**
- 合成的 Codable 对可选属性使用 `decodeIfPresent`，没有这个字段的旧密文可以照常解码。项目还没有发布，不需要额外的兼容层。
- 修改验证码会生成一个新版本，冲突处理与其他字段一致。
- **不放进自动填充快照**，扩展里看不到这个字段。

## 解析与生成（AegisCore，纯函数，配测试）

- `OneTimePassword.parse(_ input: String) throws -> OneTimePassword`：接受 URI 或纯 Base32。Base32 忽略空白字符（空格、换行、制表符）和大小写，可以省略填充。拒绝空密钥、HOTP、未知算法，以及位数不在 6...8 或周期不在 1...300 秒的情况。
- `code(at date: Date) -> String`：用 CryptoKit 计算 HMAC，再做动态截断（RFC 4226 §5.3）。
- 测试使用 RFC 6238 附录 B 的官方测试向量，覆盖三种算法。另外测试解析的边界情况和规范化往返。

## 界面

- **编辑器**：登录条目新增「两步验证」区域，包含粘贴框、「从图片识别二维码」按钮和删除按钮。保存前校验，出错就地提示。
- **详情页**：显示当前验证码（按 3+3 分组）、剩余秒数进度圈和复制按钮。密钥本身不显示。
- **快速复制**：右键菜单和 Mac 快速搜索面板加「复制验证码」。Mac 菜单快捷键用 ⌃⌘C，面板里用 ⌥↩。
- 复制沿用 `SecureClipboard`，剪贴板 30 秒后清除。

## 安全提示

验证码和密码存在同一个保险库里，主密码一旦泄露，两步验证就不再是独立的第二因素。1Password 等产品也是这样做的。编辑器在填写验证码时用一行说明这个取舍。

## 决定（2026-11-22）

- 只做 TOTP；HOTP 与相机扫码不做。
- 快捷键：Mac「记录」菜单 ⌃⌘C，快速搜索面板 ⌥↩。
- 安全提示以一行静态说明显示在编辑器的「两步验证」区域，不弹窗。
- iOS 从照片选择二维码图片，Mac 从文件选择；均不需要相机权限。
