# 深度审查与优化路线（2026-11-19）

目标：让 Aegis 能替代 1Password 作为日常密码管理器。本文基于代码静态审查（加密、存储、iCloud 同步、自动填充扩展、局域网传输、会话管理），未运行构建或测试。每完成一项勾选并附上提交号。

## 总体判断

密码学基础扎实：

- **密钥结构**：Argon2id 派生密钥包裹随机保险库密钥；条目使用 AES-GCM，AAD 绑定 vault / item / revision ID 与父版本。
- **同步模型**：不可变版本图，并发编辑保留为冲突，不做后写覆盖。
- **局域网传输**：128 位带外配对码 + HMAC 质询，内容再由 ABB 加密备份保护。
- **锁定与剪贴板**：锁定清除内存密钥；剪贴板仅本机、限时过期；后台显示隐私遮罩。

替代 1Password 的主要障碍不在安全，而在**日常体验缺口**和**数据量增长后的性能**。

## 前提：分发路线

iCloud 同步与系统自动填充依赖描述文件授予的受限权限。免费 Apple ID 个人团队无法使用 iCloud 容器，侧载应用每 7 天需重签。

- [x] 决定路线（2026-11-19）：不付开发者年费，使用免费签名。
  - 实机确认免费证书无法开启自动填充；iPhone 上接受从 App 复制粘贴密码。
  - 已移除 iCloud 同步（CloudKit 代码、权限、界面与配置）。
  - 设备间同步改走局域网，首版范围和验证方式见 [局域网持续同步设计](LAN_SYNC_DESIGN.md)。
- [ ] 免费签名真机安装 iPhone，验证 7 天重签覆盖安装后数据仍在。

## 一、缺失功能

### P0：不做就无法真正迁移

- [x] 解锁后可预览、勾选并加密导入 **1Password 和 Chrome CSV**，完全重复的条目会跳过。
- [ ] 支持 1Password `.1pux`、Safari CSV 和 Bitwarden JSON。
以下两项依赖自动填充，免费签名下不可用，暂缓：

- [ ] **自动填充支持生物识别**：`App/Services/DeviceKeyStore.swift` 未设置 `kSecAttrAccessGroup`，扩展读不到设备密钥，每次填充都要输入主密码。需要共享钥匙串访问组，并评估扩展内的解锁流程。
- [ ] **QuickType 建议栏**：未使用 `ASCredentialIdentityStore` 注册凭据标识；`provideCredentialWithoutUserInteraction` 一律返回需要用户交互（`AutoFill/CredentialProviderViewController.swift:16`）。只注册站点与用户名，不注册密码。

- [ ] **TOTP 两步验证码**：存储 `otpauth://` 密钥、生成并显示动态码；iOS 18 起支持 `ASOneTimeCodeCredential` 自动填充。
- [x] **修改主密码 / 密钥轮换**（见 [密钥轮换设计](KEY_ROTATION_DESIGN.md)，采用新保险库身份 + 迁移，未引入 epoch）：header 当前不可变（`VaultStore.saveHeader` 与 `receive` 均拒绝不同 header）。分两层：
  - 仅换主密码：重新包裹保险库密钥，成本低，但旧 header 仍在其他设备、已导出备份和自动填充快照中，**旧密码依然能解开**；
  - 真正轮换：生成新保险库密钥并重新加密全部条目，需要 header 引入 epoch / 版本号。建议直接按此设计。

### P1

- [ ] **密码健康**：弱密码、重复使用、长期未改；可选 HIBP k-anonymity 泄露查询（联网，需用户主动开启）。
- [ ] **主密码强度估算**：创建时目前只检查 `count >= 12`（`VaultCrypto.swift:48`、`UnlockView.swift:12`）。没有 Secret Key 机制时，安全性完全依赖主密码强度。
- [ ] **条目模型扩展**：`VaultItem` 为平铺结构，银行卡字段挂在所有条目上。增加自定义字段、多网址、标签 / 文件夹，以及身份、SSH 密钥、API Key、Wi‑Fi 等类型。新增字段保持可选，旧密文可继续解码。
- [ ] **密码历史**：版本图已保存全部历史，可低成本提供"查看历史版本 / 恢复旧密码"。
- [ ] **域名匹配**：目前要求主机名完全相等（`CredentialProviderViewController.swift:153`），`login.example.com` 匹配不到 `example.com`。改为按可注册域名（eTLD+1）匹配，并支持 iOS App 标识。
- [ ] **可配置时长**：自动锁定 300 秒、剪贴板清理 30 秒目前写死。
- [ ] **单词口令生成**：适合用来生成主密码。

## 二、优化点

### 性能（尽早处理）

- [x] **避免每次保存全量解密两遍**：保存和刷新共用会话内的解密缓存。相同 ID 的密文或父链接发生变化时重新认证，锁定时清空缓存。
- [x] **自动填充快照合并写入**：登录版本发生变化后合并 350 毫秒内的更新，再原子写入。
- [x] **缓存 header**：`VaultStore` 缓存已读取的 header，在写入事务成功后更新缓存。
- [x] **历史压缩**：可在修改主密码时选择移除被取代的版本。当前版本、冲突、回收站和永久删除标记保留。详见 [密钥轮换设计](KEY_ROTATION_DESIGN.md)。
- [x] **扩展专用快照**：仅包含当前有效登录的名称、网站、用户名和密码，使用保险库密钥加密。扩展继续使用原主密码解包密钥。

### 健壮性

- [x] **坏记录隔离**：本机读取跳过无法解码、认证或通过结构校验的版本，保留原始记录。保险库部分可读时可查看和复制，并持续提示版本可能较旧。暂停条目修改、自动清理和自动填充快照发布。
